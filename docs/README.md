# OctoAcme Project Management Docs

This collection brings together the core project management guidance used by OctoAcme so teams can quickly understand the lifecycle, artifacts, and operating rhythm for cross-functional delivery work.

## Project management lifecycle

OctoAcme work starts by validating the business need, aligning stakeholders, and agreeing on success criteria. Once the problem is clear, the team plans scope, backlog, milestones, risks, and dependencies to create a delivery-focused plan. Execution then moves into iterative delivery with day-to-day tracking, quality checks, communication, and escalation of blockers. When work is ready, releases are prepared with readiness reviews, deployment verification, and rollback planning. After delivery, the team closes the work with retrospectives and continuous improvement so lessons are captured and applied to the next cycle.

## Core roles and key artifacts

Across the lifecycle, the team relies on clear ownership and a few shared artifacts:

- Project Manager (PM): coordinates delivery, schedules, risk, and communication
- Product Lead / Product Manager: defines problem, priority, and success criteria
- Developers: implement solutions and maintain quality
- QA / Testing: validate acceptance and release readiness
- Stakeholders: provide input, priorities, and approvals

Key artifacts include the project one-pager, roadmap and release plan, backlog, risk register, acceptance criteria, and retrospective action items. These artifacts help teams stay aligned from initiation through closeout.

## How to use this collection

Use the overview to orient yourself to the OctoAcme approach, then move into the specific document that matches your current phase or need. A project may start with initiation, move into planning, then use execution and release guidance as work progresses. The process docs are designed to be complementary and practical, with each one elaborating on a different part of the lifecycle.
